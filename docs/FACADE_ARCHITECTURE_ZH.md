# 建筑立面家族、真实开口与可编辑 LOD · v0.4

这次升级把立面从统一的外挂窗格，改成「用途分类 → 家族布局 → 原生几何 → 成对近远景」的流程。目标是更可信、可编辑的建筑白模。它仍是基于地图体块的建筑设计推断，不是照片重建、建筑测绘或真实室内复原。

源码按职责分为三个不依赖 Blender 的层：`facade_styles.py` 负责家族与分类，`facade_layout.py` 负责楼层、开间、开口和邻楼约束，`facade_geometry.py` 负责墙面、洞口侧壁及构件网格。`facades.py` 将结果接入 Blender 对象、材质、元数据和近景／简化配对。

## 八种建筑家族

| 配置键 | 建筑语言 | 对比样例高度 |
| --- | --- | ---: |
| `house` | 小尺度住宅、独立穿孔窗、较疏的开间 | 7 m |
| `apartment` | 公寓重复开间、较高窗洞、阳台与栏杆节奏 | 18 m |
| `office` | 规整办公窗格、清楚的楼层与竖向开间 | 21 m |
| `office_ribbon` | 水平长窗和连续带状构图 | 24 m |
| `warehouse` | 大体块、较少且偏高的窗、仓储式节奏 | 8 m |
| `retail` | 更大的底层展示面与商业开间 | 7 m |
| `curtain_wall` | 大面积玻璃、细密连续竖梃与深色层间板 | 38 m |
| `blank` | 实墙、服务建筑及不适宜套用普通窗格的体块 | 12 m |

这些是规则家族，不是八张纹理，也不是对每栋建筑的事实断言。实际开间数、楼层数与剩余墙宽受建筑尺寸约束；小体块、短边及不满足安全间距的位置可以少开窗或不开窗。高度、宽度、用途不同，不应得到同一种密度的窗格。

有合理的 `building:levels`／`building:min_level` 时，楼层布局会优先参考它们；明显不合理的层高、层数或无法与架空起始高度对应的数据会回退到高度先验。仓储家族保持单层大空间规则。这仍不等于恢复真实楼板位置。

## 分类依据与可复现性

`facade_styles.py` 是不依赖 Blender 的分类模块。优先级为：

1. 明确的手动覆盖：先采用配置中的逐栋 `facade_style_overrides`，否则采用全局 `facade_style`；值为 `AUTO` 时仍可读取输入标签中的 `facade:style`。
2. 已有用途标签：例如住宅、公寓、办公室、仓库、零售或服务设施。
3. 用途不详时，才结合高度、占地面积与稳定种子选择保守的家族。

办公用途已知，也不代表已知它真实的玻璃比例或窗型。`office`、`office_ribbon`、`curtain_wall` 之间的进一步选择，仍可能采用尺寸先验和确定性变化。学校、医院等按通用公共建筑处理；宗教等特殊建筑不假装恢复其专有立面，保留较保守的实墙家族。

同一配置种子、建筑身份和输入几何产生相同结果，不依赖遍历建筑的先后顺序。身份优先使用 `osm_id`，没有地图 ID 时使用对象名。重命名无 ID 的合成对象可能改变其稳定种子。生成后的建筑根对象可检查 `ww_facade_style` 与 `ww_facade_seed`；前者是实际家族，后者是以字符串保存的稳定生成种子。`ww_facade_style_source` 记录分类依据，`ww_facade_openings` 记录实际开口数。这些是结果记录，不是会自动重建网格的实时旋钮。

### 配置示例

```json
{
  "seed": 42,
  "facade_style": "AUTO",
  "facade_style_overrides": {
    "way/123456": "apartment",
    "Gallery_Ribbon_Office": "office_ribbon",
    "Gallery_Blank_Wall": "blank"
  },
  "lod_mode": "ALL",
  "lod_distance": 85,
  "export_detail": "CURRENT"
}
```

覆盖字典的键必须匹配对象保存的实际 `osm_id` 字符串或对象名；示例的 `way/123456` 只是占位示例，不能假定地图导入一定使用这个格式。合法家族键见上表；`AUTO` 表示继续使用自动分类。修改配置后需显式重新生成才会采用新布局。重新生成会覆盖生成区域的手动修改，应先另存文件。

插件面板中的 **Facade family** 对应全局 `facade_style`，默认 `AUTO`。手动选择具体家族后，新生成的建筑默认使用该家族；逐栋覆盖仍优先。仅切换选项不会自动改写已经手工编辑的网格。

## 真正的窗洞，而不是把窗片贴在完整墙上

近景建筑由墙面分片围出开口，洞口有向内的侧壁／窗洞进深，玻璃位于外墙面之后。窗框、窗台、阳台板与栏杆也是原生网格。侧向近看应能读到洞口边缘、凹入玻璃和外挑构件的空间关系。

近景显示时，完整的原始外壳不会继续堵在窗洞后方；它保留为配对的简化外壳，在远景模式下使用。近景墙体与简化外壳互斥，避免双层重叠、遮住窗洞与深度闪烁。`blank` 家族保留实墙是有意的设计，不是漏生成窗口。

幕墙家族另外使用连续竖梃与独立的深色 `spandrels` 层间板语义组，区别于以较宽实墙水平带分隔的 `office_ribbon`。语义分组便于单独改材质与编辑，不意味着原地图提供了真实幕墙构造信息。

开口证明的是外墙几何有深度，不意味着已经生成真实室内。玻璃后面的深色不代表测绘到的房间、楼板、走廊、家具或使用状态；当前没有推断真实户型或室内交通。

## 近景与简化外壳如何保留编辑

- 建筑根对象仍保留稳定名字、地图元数据与父子关系，`ww_kind=building`。
- 原始体块作为简化外壳保存在 `WW_Buildings` 下的配对集合；近景墙体与立面构件属于 `WW_Facades`。
- 使用 `WW_Buildings.all_objects` 遍历所有建筑；不要再假设根对象全部直接位于 `WW_Buildings.objects`。
- `ALL` 显示启用的近景立面，`COARSE` 使用完整简化体块，`AUTO` 按活动场景相机到建筑包围盒的距离选择，`FROZEN` 保留当前选择。
- 切换 LOD 或显示开关只调整集合可见性，不重新执行建筑布局，不覆写艺术家编辑过的顶点、材质与单对象隐藏状态。
- 近景和远景是两个可编辑表示。编辑近景墙体不会自动把同一改动传播到简化体块；需要两者一致时，请分别检查和编辑。

移动建筑根对象时，子级立面跟随。使用真实网格编辑即可调整窗洞和构件，无需贴图编辑器或在线素材服务。保存 `.blend` 会保存几何及当前可见状态；动态相机切换需要插件运行，GLB 则是导出时选定的固定几何快照。

## 邻楼与开口的保守处理

邻楼轮廓参与立面安全筛选，紧贴邻楼、狭缝或构件可能穿入邻楼的位置会压制开口／外挑细节。它偏向避免穿帮，而不是尽量铺满每个立面。

这种筛选是保守的平面障碍判断，不能等同于精确的三维采光、消防间距或视线模拟。高低错落的邻楼可能使本来能开窗的高层区域也被抑制；复杂凹角、连体建筑和不完整地图仍需人工检查。没有足够证据时宁可留墙，也不生成看似真实的共墙窗户。

## 已知地图事实与设计推断

- 地图可以提供：建筑轮廓、来源 ID、用途标签，以及可能存在的高度／层数。高度仍应查看原有 `height_source`，不能把缺失高度的估算值当作测量值。
- 程序推断：家族选择中的尺寸先验、开间、窗数、窗高、窗框、阳台、玻璃和立面构图。
- 手动指定：用户在配置中强制选择的家族；这表示设计意图，不表示新增了测绘证据。
- 八栋比较样例全部为原创合成体块，没有真实地址或伪造 OSM ID。其用途标签用于展示规则，家族由明确覆盖固定。

导入 OSM 场景仍须保留原地图的归属和许可。此比较场景本身不包含 OSM 地图。

## 生成与检查对比场景

在项目根目录运行：

```sh
blender -b --factory-startup --python-exit-code 1 --python scripts/render_facade_families.py
```

输出独立保存在 `artifacts/facade_v04/`，不覆盖 v0.3：

- `facade_families.png`：八种家族的带标签透视比较图。
- `facade_recess_closeup.png`：公寓立面的斜向近景，用于检查洞口和阳台深度。
- `facade_families.blend`：米制、原生可编辑场景，保存总览相机，并保留近景相机。
- `facade_families.glb`：所有启用近景细节的固定快照，含可移植网格标签。
- `facade_families_manifest.json`：每例的家族、高度、稳定种子、开口数、网格统计，以及渲染参数与源码 SHA-256。

渲染与 `.blend` 保留大面积中性背景地面；GLB 导出时仅将背景地面临时缩为 240 m，避免外部查看器的「显示全部」被 2 km 的摄影背景撑大。建筑、标签、相机与照明不因此改变，导出后恢复 Blender 地面尺寸。

命令末尾添加 `-- --quick` 可降低采样和分辨率；`-- --no-render` 只构建、检查和导出；`-- --skip-closeup` 跳过近景图；`-- --output <目录>` 改变输出目录；`-- --seed 42` 改变生成种子。总览使用透视相机和中性地面，展示同一米制尺度下的真实体量差异，不把每栋楼拉成相同高度。

## 支持边界

当前支持由本项目 `scene.building` 建立的、有序上下轮廓挤出壳体，以及由该流程生成的近景／简化配对。它不是对任意导入建筑网格的自动拓扑识别或打洞工具。

不承诺：将任意已经改过拓扑的旧壳体转换为新立面、对任意手工建筑进行无损再生成、把 v0.3 外挂细节自动迁移成新壳体、准确重建特殊屋顶／曲面幕墙／复杂内院，或从地图猜出真实室内。切换显示是非破坏性的；重新生成是替换操作，两者必须区分。
